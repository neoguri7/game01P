# 스타일 바이블

이 문서가 모든 에셋의 기준이다. 에이전트는 읽기만 한다. 빈칸을 채운 뒤 사용한다.

출처: 저장소 루트의 [`style.md`](../../style.md) (v4)를 옮겼다. 긴 설명과 근거는 그쪽에 있다. 두 문서가 어긋나면 사람이 정리하고,
그 전까지는 이 문서와 `style.md` 중 더 엄격한 쪽을 따른다.
**(확인 필요)** 표시는 `style.md` 가 아니라 코드/기존 매니페스트에서 추론한 항목이다. 사람이 맞는지 확인한다.

## 기본
- 장르 / 분위기: 다크 판타지 숲 폐허의 컴팩트한 그리드 택틱스 로그라이크. 벽은 뒤틀린 뿌리와 이끼 낀 바위의 근흑록색, 바닥은 이끼/고사리, 가시 함정, 깊은 숲 캐노피 배경. 재질은 어둡고 채도를 낮춰 유닛과 그리드 표시가 화면에서 가장 밝게 보이게 한다. UI 는 디아블로풍(따뜻한 근흑 석재 패널, 청동/금 장식, 핏빛 생명바). 장식보다 실루엣과 가독성이 우선이다.
- 뷰 (사이드 / 탑다운 / 아이소): **(확인 필요)** 로직은 직교 그리드, 전투 화면은 아이소메트릭 투영(셀 = 64x32 다이아몬드, `FIsoView`). 유닛은 정면을 보는 게임 스프라이트. `style.md` 는 시점 규칙을 새로 만들지 말라고 하므로, 요청에 없는 시점/원근을 추가하지 않는다.
- 캐릭터 캔버스 (px): 64x64 (게임 내 모든 에셋의 네이티브 크기). 큰 프롭은 64x96 예외가 있다. 16x16 은 애니메이션 점검용, 32x32 는 작은 아이콘용으로만 허용.
- 타일 크기 (px): 64x64. 바닥/벽/배경 타일은 불투명 셀 이미지, 아이소 바닥 타일은 투명 모서리의 다이아몬드.
- 픽셀 스케일 (게임 내 확대 배율): 최근접(nearest) 샘플링. 배율은 코드가 정한다(아이소 뷰는 0.5 단계 배율). 이미지를 미리 확대해서 만들지 않는다.

## 선과 면
- 외곽선: 캐릭터/몬스터/프롭은 어두운 단일색 외곽선, 두께 1 네이티브 픽셀(PixelLab `single color outline`). 타일은 외곽선 없음(`lineless`). **(확인 필요: 타일/캐릭터 구분은 기존 `assets/art/manifest.json` 의 생성 설정에서 가져왔다)**
- 셀프 아웃라인 (내부 선) 사용 여부: 쓰지 않는다. 내부 구분은 덩어리와 명도 차이로 한다. 모든 작은 부위에 외곽선을 두르지 않는다.
- 안티앨리어싱: 사용하지 않음 (알파는 0 또는 255 만)

## 명암과 색
- 광원 방향: 좌상단. 모든 프레임과 같은 계열 에셋에서 같다.
- 색 램프 단계 수: 미정. `style.md` 는 연속 그라데이션이 아닌 이산적인 명도 단계를 요구할 뿐 개수는 정하지 않았다. 앵커를 고른 뒤 사람이 기입한다.
- 하이라이트 / 그림자 규칙: 피사체 밖으로 번지는 캐스트 섀도, 반사, 볼류메트릭 빛, 블룸, 렌즈 효과 금지. 발광(이미시브)은 요청했을 때만.
- 팔레트: `style/palette.json` 참고. **현재 비어 있다.** `style.md` 도 확정 팔레트가 없다고 한다. 진영/선택 색은 코드가 그리는 표시 규약이므로 스프라이트 팔레트와 별개로 의미를 보존한다: 아군 파랑 `#508CFF`, 적 빨강 `#E65050`, 선택 노랑 `#FFDC3C`, 이동 가능 시안 `#00C8FF`. 어두운 중립 `#46465A`, `#14141E`. 진영을 표시하려고 생물 전체를 다시 칠하지 않는다. 형광 포인트색으로 서로 경쟁하지 않는다.

## 비율과 디테일
- 캐릭터 머리 : 몸 비율: 고정하지 않는다(`style.md`: 지금 프로토타입에 정해진 비율이 없으므로 만들어 내지 않는다). 한 칸에서 읽히는 단순화된 체형으로 머리, 주 몸통, 클래스를 드러내는 장비를 강조한다. 전사/궁수/마법사는 실루엣으로 구분된다.
- 디테일 밀도: 캐릭터, 몬스터, 프롭은 **중간 디테일**. 장비/재질/클래스가 보이되 장식 무늬와 빽빽한 내부는 피한다. 타일과 배경은 **높은 디테일**(금, 이끼, 모르타르, 마모)이되 바닥은 유닛보다 조용해야 한다. 벽은 바닥과 분명히 대비된다(따뜻하고 어두운 석조 대 차갑고 밝은 바닥).
- 사람(파티원)은 **얼굴이 없다**: 눈, 코, 입을 그리지 않는다. 후드/바이저/모자챙이 얼굴을 빈 면이나 그늘로 가린다. 몬스터는 얼굴이 있어도 된다.

## 금지
- 포토리얼, 벡터 스무딩, 회화풍 붓질, 3D 렌더, 업스케일된 픽셀 블록
- 안티앨리어싱, 블러, 부드러운 그라데이션, 과도한 디더링, 흩어진 한 픽셀 노이즈, 반투명 픽셀
- 텍스트, 워터마크, 로고, 라벨, 목업, 장식 테두리, 컨택트 시트 (이미지 한 장에 에셋 하나)
- 요청하지 않은 배경, 추가 피사체, 구운 격자선, 환경 에셋 안의 캐릭터/UI
- 요청하지 않은 슬롯 프레임, 희귀도 테두리, 진영 표시
- 프레임 크기가 서로 다른 시트, 잘린 팔다리/장비(여백을 둔다)
- 카메라 이동, 크기 변화, 모핑, 깜빡임, 애니메이션 중 추가되는 물체
- 기존 PNG 를 자동으로 레퍼런스로 쓰는 것. 앵커와 `spec.references` 에 적힌 승인 파일만 쓴다.

## 프롬프트 고정 문구
모든 생성 프롬프트 맨 앞에 그대로 붙인다. 종류별 차이(외곽선 유무, 배경 투명/불투명, 크기)는 여기에 넣지 않고 `spec.prompt_asset` 과 도구 파라미터로 전달한다.

```
dark fantasy forest, compact readable game pixel art, hard pixel edges, no anti-aliasing, no gradients, no noise, simple discrete value steps, light from top-left, restrained desaturated palette
```

## 앵커 목록 (`style/anchors/`)
`style.md` 는 승인된 레퍼런스 이미지가 아직 없다고 한다. 앵커는 사람이 직접 고른다(기존 `assets/art` 의 PNG 를 쓰려면 사람이 골라서 복사한다).
앵커 폴더는 `style/anchors/<지문 이름>/` 이다: `character`(스프라이트와 시트 공용), `tile`, `object`(맵 오브젝트), `item`(아이콘), `ui`.
