# Development Workflow

## Principle

Use macOS and WSL as lightweight coding environments. Use native Windows as the
authoritative build, run, and toolchain environment.

```text
macOS / WSL
  - edit code
  - use Neovim, rg, git, clangd, Codex
  - review diffs and architecture
  - avoid heavy local builds by default

Windows PC
  - own native MSVC/CMake/vcpkg builds
  - run SDL and future Windows-only tools
  - run Unreal or other GPU/CPU-heavy tools
  - produce final verification result
```

## Local Windows Check

Run this from PowerShell on the Windows PC:

```powershell
.\scripts\check-windows.ps1 -Configuration Debug
```

Release build:

```powershell
.\scripts\check-windows.ps1 -Configuration Release
```

Clean rebuild:

```powershell
.\scripts\check-windows.ps1 -Configuration Debug -Clean
```

Run after build:

```powershell
.\scripts\check-windows.ps1 -Configuration Debug -Run
```

Requirements:

- Visual Studio 2022 or Visual Studio Build Tools
- CMake
- vcpkg
- `VCPKG_ROOT` set to the vcpkg checkout

## Lightweight Editor Support

The repository includes a `.clangd` fallback so Neovim/clangd can parse project
headers with C++23 and the local `src/` include path even when macOS or WSL is
not configured for a full build.

For exact diagnostics, prefer a compile database generated by the Windows build.
For lightweight editing, the fallback is enough to browse local components,
systems, factories, and core headers.

## Remote Check From macOS or WSL

Set these in your shell profile or per command:

```bash
export GAME01P_WIN_HOST="your-windows-host"
export GAME01P_WIN_USER="your-windows-user"
export GAME01P_WIN_PORT="22"
export GAME01P_WIN_REPO="C:/dev/game01P"
export GAME01P_WIN_CONFIG="Debug"
```

Then run:

```bash
./scripts/remote-windows-check.sh
```

Optional Wake-on-LAN:

```bash
export GAME01P_WOL_MAC="00:11:22:33:44:55"
```

Optional branch checkout before build:

```bash
export GAME01P_WIN_BRANCH="feature/my-work"
```

Optional sleep after build:

```bash
export GAME01P_REMOTE_SLEEP=1
```

## Working Rule

Use git as the sync boundary between machines.

```text
1. Edit on macOS or WSL.
2. Commit or push the branch.
3. Wake or SSH into the Windows PC only when verification is needed.
4. Run the native Windows check.
5. Use the Windows log as the source of truth for build failures.
```

Avoid building directly from a network share. Keep a normal clone on each
machine and sync with git.
