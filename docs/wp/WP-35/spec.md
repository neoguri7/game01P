### 3a. Proving-test grammar (used by every WP's `features.json`)
- `node:<repo-relative file>::<test name>` — a `node:test` test. When the WP has at least one `node:` feature, the gate runs `node --test --test-reporter=junit --test-reporter-destination=<worktree>/out/node-junit.xml <files…>` in the worktree for all `node:` files of the WP; proven when a `<testcase name="<test name>">` has no `<failure>`/`<skipped>`.
- `ctest::<ctest test name>` — proven when the name is in `evidence.ctest.passed`.
- `<ctest test name>::<Case>` — a case of a C++ feature test; proven when `evidence.cases.passed` contains exactly `<ctest test name>::<Case>` AND `tests/features/<ctest test name>.cpp` contains the text `"<Case>"`.

`features.json` schema (every WP): `{"wp": "<id>", "files": [<repo-relative path>], "allowTimeoutChange": <bool, default false>, "allowCheckDrop": [<repo-relative test file>], default [], "features": [{"id", "behavior", "test", "passes"}]}`; a missing optional field means its default.

### 3b. Evidence (`<worktree>/out/evidence.json`, written by `runBuild`)
`{ "sha": <HEAD sha>, "dirty": <bool: git status --porcelain --untracked-files=no non-empty>, "preset": <string>, "configured": <bool: configure ran this time>, "build": {"ok": <bool>, "errors": [<string>]}, "ctest": {"ran": <bool>, "passed": [<name>], "failed": [<name>], "notRun": [<name>]}, "cases": {"passed": ["<ctest name>::<case>"]} }`. With `--no-test`, `ctest.ran` is false and its arrays are empty. ctest runs as `ctest --preset <p> --output-junit <absolute path of out/ctest-junit.xml> --test-output-size-passed 1048576 --test-output-size-failed 1048576 [-R <regex>]`; `cases.passed` comes from each JUnit testcase's `system-out` lines `[ ok ] <Case>`, prefixed with that testcase's name.
`ERROR_RE = /\b(?:fatal )?error [A-Z]+\d+\s*:|: error:|LINK : fatal error/`.

### 3c. Gate (`node .claude/scripts/wp-gate.mjs <id> --worktree <path> --base <sha>`)
Reads `features.json` from the base commit (`git show <base>:docs/wp/<id>/features.json`) and evidence from `<worktree>/out/evidence.json`. Changed paths = `git diff --name-status -M <base>..HEAD` in the worktree (a rename counts as its old and new path). Prints `{"ok": <bool>, "rules": [{"id", "detail"}], "features": [{"id", "test", "passes"}]}` to stdout; exit 0 when `ok`, else 1. Rule ids:
`branch` (current branch ≠ `wp/<id>`) · `dirty` (tracked changes uncommitted) · `scope` (a changed path outside `files` ∪ {`docs/wp/<id>/progress.md`, `docs/wp/<id>/decisions.md`}) · `spec-edit` (`docs/wp/<id>/spec.md` or `features.json` changed) · `test-deleted` (a file under `tests/` deleted) · `check-drop` (for a `.cpp`/`.h` under `tests/` present at base and not listed in `allowCheckDrop`, count of `/\bCHECK\s*\(/g` at HEAD < at base) · `timeout` (the multiset of `/TIMEOUT\s+(\d+)/g` over all tracked `CMakeLists.txt` differs between base and HEAD, unless `allowTimeoutChange` is true) · `evidence-missing` · `evidence-sha` (≠ HEAD) · `evidence-dirty` · `build-failed` · `ctest-failed` (`failed` or `notRun` non-empty) · `feature-unproven`.

- Create `.claude/scripts/lib/locks.mjs` — `export class LockTimeout extends Error`; `export async function acquireLock(file, {timeoutMs = 1800000, pollMs = 2000} = {}) → release()`. Create with `fs.openSync(file, 'wx')`, write `{"pid": process.pid, "started": Date.now()}`; on EEXIST read the owner; empty or invalid JSON = alive; dead iff `process.kill(pid, 0)` throws `ESRCH` (EPERM = alive) → delete and retry; timeout → `throw new LockTimeout(file)`. Create parent directories.
- Create `.claude/scripts/lib/evidence.mjs` — `export function filterBuildOutput(text) → string[]`, `export function parseJUnit(xml) → {passed, failed, notRun, casesPassed, outputs: {name: string}}` (ctest JUnit: `status="run"` + no `<failure>` = passed; `status="notrun"` or `<skipped>` = notRun), `export function featureSet(repoDir) → string[]` (sorted file names).
- Create `.claude/scripts/lib/runner.mjs` — `export async function runBuild({cwd, preset = 'windows-msvc-agent', noTest = false, tests, run, lockRoot = path.join(process.env.LOCALAPPDATA, 'game01P')}) → {exitCode, evidence, report}`. `run(cmd, args) → Promise<{code, output}>` (stdout+stderr); every external command, including `git`, goes through `run`. Computed vcpkg dir = `<lockRoot>/vcpkg_installed/<first 12 hex of sha1(read(cwd/vcpkg.json) + read(cwd/vcpkg-configuration.json))>` (a missing file reads as `''`). Order: take `<cwd>/out/build.lock` → if F6 → take `<lockRoot>/configure.lock`, run `cmake --preset <preset> -DVCPKG_INSTALLED_DIR=<computed dir>`, release → `cmake --build --preset <preset> --parallel` (F7 retry) → unless `noTest`: take `<lockRoot>/ctest.lock`, run ctest per §3b, release → `sha` from `run('git', ['rev-parse','HEAD'])`, `dirty` from `run('git', ['status','--porcelain','--untracked-files=no'])` → write evidence → release `build.lock`. Exit codes: 0 green, 1 configure failed, 2 build failed, 3 tests failed, 4 lock timeout.
- Create `.claude/scripts/build.mjs` — CLI only: parses `[--preset <p>] [--no-test] [--tests <regex>]`, calls `runBuild` with a real `run` (`child_process.spawn`, no shell), prints `report`, exits with `exitCode`.
- Create `.claude/scripts/wp-gate.mjs` — §3c and F10.
- Create `.claude/scripts/wp-merge.mjs` — F11–F13. CLI: `node .claude/scripts/wp-merge.mjs <id> --reviewed <sha> [--build-cmd "<cmd>"]`; default build command `node .claude/scripts/build.mjs`; `--build-cmd` runs with `shell: true` in the repo root. Worktree path = the `worktree` entry whose `branch` is `refs/heads/wp/<id>` in `git worktree list --porcelain`; base = `git merge-base main wp/<id>`; the gate is spawned as `node <repo>/.claude/scripts/wp-gate.mjs <id> --worktree <path> --base <base>`.
- Create `.claude/scripts/test/presets.test.mjs`, `build.test.mjs`, `gate.test.mjs`, `merge.test.mjs` (`node:test` + `node:assert/strict`; test names exactly as in §3).

## 7. Tests
- **build.test.mjs** feeds recorded text to `filterBuildOutput`/`parseJUnit` (inline fixture strings: an MSVC log with duplicate `error C2065` lines, an LNK error, warnings; a ctest JUnit with one passed testcase whose system-out has `[ ok ] A`, one failed, one notrun) and drives `runBuild` with a fake `run` that records calls and returns scripted `{code, output}` — e.g. first build returns `MSB3073` then success (F7); `CMakeCache.txt` absent vs present with a changed feature set in a temp dir (F6). Every `runBuild` call in tests passes `lockRoot` = a fresh temp dir, never the real `%LOCALAPPDATA%`. `Locks` uses a temp dir: a lock held by `process.pid` blocks a second acquire until release (short `timeoutMs` → `LockTimeout`); a lock file naming a dead PID (spawn `node -e ""`, wait for exit, use its pid) is taken over.
- **gate.test.mjs** builds a temp git repo (`git init -b main`, local `user.name`/`user.email` set in the repo config): base commit with `docs/wp/X/spec.md` (`# X: Title`), `features.json` (`files: ["a.txt", "t.test.mjs"]`, one feature `node:t.test.mjs::Alpha`, one `suite_tests::Beta`), `tests/features/suite_tests.cpp` containing `CHECK(1); CHECK(2); CHECK(3); {"Beta", Beta}`, `CMakeLists.txt` with `TIMEOUT 30`, `.gitignore` with `out/`; then `git worktree add -b wp/X`. One branch per rule (edit `b.txt`; edit `spec.md`; delete the test file; drop to 2 CHECKs (and the same drop with the file listed in `allowCheckDrop` asserting no `check-drop`); `TIMEOUT 60`; evidence sha wrong; uncommitted change; wrong branch name; evidence with a failed ctest) asserts exit 1 and the rule id. The clean branch (`t.test.mjs` with a passing `test('Alpha')`, evidence with `cases.passed: ["suite_tests::Beta"]`) asserts exit 0 and both `passes: true`; removing `Beta` from evidence asserts `feature-unproven`.
- **merge.test.mjs** reuses that fixture with an empty `features` list and `--build-cmd "node -e process.exit(0)"` / `"node -e process.exit(1)"`; asserts main HEAD, the commit message `X: Title`, worktree removed and branch gone (F12), and main unchanged plus worktree kept (F13 and each F11 refusal). F13 has two cases: the red build stub, and a squash conflict (main and `wp/X` each commit a different edit to the same line of `a.txt`) — both assert exit 1, main HEAD unchanged with a clean tree, worktree and branch kept.
- No existing C++ test, assertion or timeout changes.

## 8. Decisions
- Node (≥22, installed) for all agent tooling; testable with `node:test`.
- The gate is run by the design session after the implementer reports, not as a hook (subagent Stop hooks are undocumented here). The gate itself runs `node:` tests so tooling WPs prove themselves.
- `Embedded` (/Z7) only in the agent preset; developer presets keep Edit-and-Continue.
- `VCPKG_INSTALLED_DIR` is shared per user and keyed by the manifest hash, so worktrees with the same `vcpkg.json` reuse one install and a different manifest gets its own directory; configure steps are serialized by `configure.lock`.
- Out of scope: forest-mode removal (WP-36), CI workflow changes, balance simulation.

## 9. Pitfalls
- Long commands: pass an explicit tool timeout ≥600000 ms; a default-timeout call is moved to the background, which caused PDB collisions before.
- Until T2 exists, build with raw `cmake --preset windows-msvc-agent` / `cmake --build --preset windows-msvc-agent` / `ctest --preset windows-msvc-agent`.
- One build/ctest per worktree at a time; MSB3073/3075 is a transient DLL-copy lock.
- `out/` is gitignored, so evidence files never dirty the tree.
- `python3` is a stub; scripts are Node only.
