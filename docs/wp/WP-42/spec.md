# WP-42: Playtest instrumentation — run-log additions, log report tool, fast windowless runs, playtest folder

Size: L · Player-facing: no · Certainty: settled · Base commit: the commit that adds this spec · Branch: wp/WP-42

## 1. Goal [S]
The first human playtest of WP-39/40/41 and every later design ruling (`docs/design/proposals.md` P3, P6, P10) rest on numbers the run log cannot give today. This WP adds the missing log keys (P2), a tool that turns run logs into the P2 metrics, a fast windowless mode so a seed batch finishes in minutes, and the `docs/playtest/` folder with a session template. Nothing the player sees or does changes: no rule, number, screen or string.
- Decisions it rests on: `proposals.md` P2 (the key list and the seven metrics) and P10 (the preparation steps); `.claude/CLAUDE.md` "Playtest loop". No `decisions.md` ruling is changed.

## 3. Behaviors [S]
"The log" is the per-run JSONL written by `FRunLog`. All new keys are optional keys or new line types; `kRunLogSchemaVersion` stays 1.

| ID | Behavior | Proving test |
|---|---|---|
| F1 | WHEN a rune offer is resolved (pick or skip) THEN the `offer` line SHALL carry `candidates`: the offered rune ids, in the same order as `rarities`. | `run_log_tests::OfferRecordCarriesCandidates` |
| F2 | WHEN the run enters the Camp phase THEN the log SHALL get one `camp_enter` line with `depth`, `party_hp_before_heal`, `party_hp`, `party_hp_max`, `materials`, `ms`, `frame`, written after the `dungeon_clear` line. | `run_log_tests::CampEnterRecordsEntryState` |
| F3 | WHEN `LeaveCamp` succeeds THEN the log SHALL get one `camp_leave` line with the camp's `depth` (before the increment), `materials`, `ms`, `frame`; a refused `LeaveCamp` (open offer) SHALL write none. | `run_log_tests::CampLeaveRecorded` |
| F4 | WHEN a `room_end` line is built THEN it SHALL carry `ms` (`RunLogMilliseconds()`) and `frame` (`RunLogFrameIndex`). | `run_log_tests::RoomEndCarriesClock` |
| F5 | WHEN an attack intent whiffs THEN `FIntentStats::whiffReasons[reason]` SHALL grow by 1 together with `whiffed`, so the reason counts always sum to `whiffed`. | `intent_tests::WhiffReasonsCounted` |
| F6 | WHEN a `room_end` line is built THEN `intents.whiff_reasons` SHALL be an object reason → count copied from the same battle's stats (empty object when nothing whiffed or the stats belong to another battle). | `run_log_tests::RoomEndCarriesWhiffReasons` |
| F7 | WHEN a `BossDefeated` run event is delivered THEN the log SHALL get one `boss_defeat` line with `depth`, `room`, `boss` (the event id) and `slot` (`"mid"`, `"final"`, or `""` when the slot is unknown). | `run_log_tests::BossDefeatRecordsSlot` |
| F8 | WHEN the `run_end` line is written THEN it SHALL carry `start_depth` (the `depth` of the log's first `run_start` line; key absent when the log has none) and `final_bosses` (the number of `boss_defeat` lines with `slot == "final"` in the log). | `run_log_tests::RunEndCarriesStartDepthAndFinalBosses` |
| F9 | WHEN fast-forward is on THEN a frame SHALL use the fixed step `kScriptFixedDeltaSeconds` and SHALL NOT rasterize, except a frame on which a capture is due; WHEN it is off THEN the frame plan SHALL equal today's behavior. | `headless_tools_tests::FastForwardFramePlan` |
| F10 | WHEN the report library parses log text THEN unparsable lines SHALL be skipped and the rest returned in order. | `node:.claude/scripts/test/runlog.test.mjs::parse skips broken lines` |
| F11 | WHEN logs are aggregated THEN battles SHALL report count, wins, defeats, mean rounds, mean first-damage round (rooms with 0 excluded), mean wall seconds and mean sim seconds (frames / 60), each also split by elite. | `node:.claude/scripts/test/runlog.test.mjs::battle metrics` |
| F12 | WHEN logs are aggregated THEN skill use SHALL be reported per party member from `room_end.skills_by_member` as count and share of that member's uses, and a share ≥ 0.60 or ≤ 0.05 SHALL be flagged. | `node:.claude/scripts/test/runlog.test.mjs::skill shares per member` |
| F19 | WHEN an accepted skill command of a party unit is counted into `skillsUsed` THEN it SHALL also be counted into `FRoomBattleStats::skillsByMember[<unit id>][<skill id>]`, enemy commands SHALL NOT be, and `room_end` SHALL carry the map as `skills_by_member`. | `run_log_tests::SkillsCountedPerMember` |
| F13 | WHEN logs are aggregated THEN each rune SHALL report offered, picked and pick rate; each rarity offered and picked; and the skip rate over all offers. Offers without `candidates` count only toward rarity and skip figures. | `node:.claude/scripts/test/runlog.test.mjs::rune pick rates` |
| F14 | WHEN logs are aggregated THEN forks SHALL report, per `kind`, the count, the variant rate (`choice == 1`) and the mean HP fraction at the choice; events SHALL report a count per (event, choice). | `node:.claude/scripts/test/runlog.test.mjs::fork and event choices` |
| F15 | WHEN logs are aggregated THEN camps SHALL report visits, mean entry HP fraction before and after the free heal, mean entry materials, spend per `camp.id` (count and total) and mean stay seconds; a `camp_enter`/`camp_leave` pair with a `log_session` line between them SHALL be left out of the stay mean. | `node:.claude/scripts/test/runlog.test.mjs::camp metrics` |
| F16 | WHEN logs are aggregated THEN each whiff reason SHALL report count and rate = count ÷ (committed − invalidated), and the rate SHALL be 0 when the denominator is ≤ 0. | `node:.claude/scripts/test/runlog.test.mjs::whiff rates by reason` |
| F17 | WHEN the report text is formatted THEN it SHALL contain the eight section headings of §5 in order, and a metrics object built from zero runs SHALL format without throwing. | `node:.claude/scripts/test/runlog.test.mjs::report sections` |
| F18 | WHEN the baseline runner builds the environment for a seed THEN it SHALL set exactly the variables listed in §5 for `baseline.mjs`, with the save directory under `out/baseline/<label>/seed-<n>`. | `node:.claude/scripts/test/runlog.test.mjs::baseline environment` |

### Create (tooling, Node ≥ 20, no dependencies, ES modules)
- `.claude/scripts/lib/runlog.mjs` — pure functions:
  - `parseRunLog(text) → object[]` (F10).
  - `aggregate(runs) → metrics`, `runs` = array of line arrays (one per log file). Shape:
    `{ runs: {count, results: {<result>: n}, meanDungeonsCleared, finalBosses, startDepths: {<depth>: n}}, battles: {all, normal, elite} each {count, wins, defeats, meanRounds, meanFirstDamageRound, meanWallSeconds, meanSimSeconds}, skills: {<memberId>: {<skillId>: {count, share, flag}}} with flag "high" | "low" | "", runes: {byRune: {<id>: {offered, picked, rate}}, byRarity: {<rarity>: {offered, picked}}, offers, skipped, skipRate}, forks: {<kind>: {count, variantRate, meanHpFraction}}, events: {<eventId>: {<choice>: n}}, camps: {visits, meanHpFractionBeforeHeal, meanHpFraction, meanMaterials, spend: {<id>: {count, total}}, meanStaySeconds}, whiffs: {denominator, byReason: {<reason>: {count, rate}}} }`.
    Input keys (all read with a default when absent: numbers 0, strings `""`, arrays `[]`, objects `{}`):

    | Metric | Line `t` | Keys read |
    |---|---|---|
    | runs | `run_end` | `result` (string), `dungeons_cleared`, `final_bosses`, `start_depth` (a run without a `run_end` line counts under result `"open"`) |
    | battles | `room_start`, `room_end` | `room_start`: `depth`, `room`, `ms`, `frame`; `room_end`: `depth`, `room`, `result` (`"win"` / `"defeat"`), `rounds`, `first_damage_round`, `elite`, `ms`, `frame` |
    | skills | `room_end` | `skills_by_member`: object member id → object skill id → count. A `room_end` without the key (an older log) adds its `skills_used` counts under member `"?"` |
    | runes | `offer` | `candidates` (rune ids), `rarities` (same order), `picked` (rune id, `""` when skipped), `picked_rarity`, `skipped` (bool) |
    | forks | `fork` | `kind`, `choice` (0 standard, 1 variant), `party_hp`, `party_hp_max` (fraction = hp ÷ max; a fork with max 0 is left out of the mean) |
    | events | `event` | `event` (id), `choice` (number) |
    | camps | `camp_enter`, `camp_leave`, `camp` | `camp_enter`: `party_hp_before_heal`, `party_hp`, `party_hp_max`, `materials`, `ms`; `camp_leave`: `ms`; `camp`: `id`, `amount`. A `camp_leave` pairs with the nearest earlier unpaired `camp_enter` of the same file. `visits` = number of `camp_enter` lines |
    | whiffs | `room_end` | `intents.committed`, `intents.invalidated`, `intents.whiff_reasons`; denominator = Σ committed − Σ invalidated over all rooms |

    Formulas: `runs.finalBosses` = Σ `run_end.final_bosses`; `meanDungeonsCleared` = mean of `run_end.dungeons_cleared` over runs that have a `run_end`. Every HP fraction mean (`forks.meanHpFraction`, both camp fractions) is the mean of the per-line ratios, never a ratio of sums; a line with max 0 is left out. `skills`: member `"?"` (older logs; `skills_used` mixes enemy uses in) never carries a flag.

    `byRune[id].offered` counts the offers whose `candidates` contain the id; `picked` counts the offers whose `picked` equals it. `byRarity[r].offered` counts entries of `rarities`; `byRarity[r].picked` counts non-empty `picked_rarity`.

    Rules: a battle's wall seconds = (`room_end.ms` − the latest earlier `room_start.ms` with the same depth and room) ÷ 1000 and sim seconds = the same on `frame` ÷ 60; a `room_end` without `ms`/`frame`, or with a `log_session` line between the pair, is left out of that mean only. A room is elite when `room_end.elite === true`. `skills` shares for a member with fewer than 20 uses in total carry flag `""`. Every mean over an empty set is `null`; every rate with a zero denominator is `0`.
  - `formatReport(metrics) → string`: plain text, one section per heading, in this order: `RUNS`, `BATTLES`, `SKILLS`, `RUNES`, `FORKS`, `EVENTS`, `CAMPS`, `WHIFFS`. Numbers with 2 decimals; `null` printed as `-`. Binding: the eight headings each on their own line in that order, one row per key under its heading with keys sorted ascending, the flag word printed after a flagged share. Each row is `<key>: <value>[, <label> <value>…]`; spacing and labels are the implementer's choice.
  - `buildRunEnv({label, seed, maxRooms = 0, policy = "default", fast = true}) → object` (F18; with `fast: false` the `GAME01P_FAST` key is omitted): `SDL_VIDEO_DRIVER=dummy`, `SDL_AUDIO_DRIVER=dummy`, `SDL_RENDER_DRIVER=software`, `GAME01P_SAVE_DIR=out/baseline/<label>/seed-<seed>`, `GAME01P_SEED=<seed>`, `GAME01P_AUTOPLAY=1`, `GAME01P_AUTOPILOT=<policy, default "default">`, `GAME01P_AUTOPILOT_MAX_ROOMS=<maxRooms>` (key omitted when maxRooms is 0), `GAME01P_FAST=1`. All values are strings; the save dir is returned in this relative form with forward slashes (F18 asserts it), and `baseline.mjs` resolves it against the repo root.
- `.claude/scripts/runlog-report.mjs` — CLI `node .claude/scripts/runlog-report.mjs <file-or-dir>… [--json]`. A directory is searched recursively for `*.jsonl`. Prints `formatReport` (or the metrics as JSON). Exit 1 with `no run logs found` on stderr when no file matches; exit 0 otherwise.
- `.claude/scripts/baseline.mjs` — CLI `node .claude/scripts/baseline.mjs --label <name> --seeds <a>-<b> [--max-rooms <n>] [--policy <text>] [--exe <path>] [--timeout-s <n>] [--no-fast]`. `--seeds` takes an inclusive range `a-b` or a single number `a`; `a > b` or a non-number exits 2 with a usage line. `--no-fast` passes `fast: false`. The repo root is two directories above the script's own directory (`import.meta.url`). ## 8. Decisions
- Resolved: camp entry records HP both before and after the free camp heal — P3's question ("is the paid heal a dead option") needs the post-heal state, P10's elite row needs the pre-heal state.
- Resolved: the victory fact is logged as `boss_defeat` lines plus `run_end.final_bosses`, not as a `result: "victory"` — a run still ends only by wipe or abandon (확정 23/156); P1 is undecided and this WP must not pre-empt it.
- Resolved: fast mode keeps every view's per-frame logic and skips only the clear, the ImGui rasterization and the present — views can open modals and move state during the render pass, so skipping the whole pass could change behavior. T7 proves equality on a real run.
- Resolved: the tools live in `.claude/scripts/` beside `build.mjs` — the gate already runs `node:` proofs from there.
- Alternatives considered [L]: a Release build for speed — rejected: one build directory (CLAUDE.md). A C++ aggregation tool — rejected: a new executable target is not needed. Logging whiff reasons as an enum — rejected: the reason strings are already the shared vocabulary of the intent log lines and the HUD.
- Defaults for anything unspecified: follow the nearest existing code in the same file; optional log keys never bump the schema version.
- Out of scope: taking the baseline itself (the design session runs it after merge); thresholds; any HUD or debrief use of the new keys; `FRunReportSummarize`; simulation configs.

## 9. Pitfalls
- One build/ctest at a time; an MSB3073/MSB3075 DLL-copy failure is a transient lock — rerun once.
- Game runs stay windowless with `GAME01P_SAVE_DIR` under `out/`; never write to `%APPDATA%\Game01P`.
- `python3` is a Store stub: use `node`.
- ImGui math operators are disabled: build `ImVec2` component-wise.
- `AppendRunEvent` during listener delivery is dropped as re-entrancy: the two new appends sit in run-flow functions, never inside a listener.
- `FIntentStats` is reset by value assignment per battle; a map member resets with it — do not add a separate clear.
- `docs/wp/WP-42/features.json` is already written by the design session; the implementer never edits it or this spec.
