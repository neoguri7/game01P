## Findings (severity-ordered)

- **[Blocker] R20 — undefined enum enumerators make slice unbuildable.** `src/core/data/EContentFieldType.h:7-13` declares only `Text, Number, Boolean, TextArray, NumberArray`, but `src/core/data/FContentLoader.cpp:23,32,46,52,66,87` and `src/gameplay/data/FUnitContent.h:35` / `src/gameplay/data/FSkillContent.h:31` reference `EContentFieldType::Id` and `EContentFieldType::IdArray`. Static proof (independent of build): no `Id`/`IdArray` enumerator exists. **Smallest fix:** add `Id, IdArray` to the enum (and update the three `-Wswitch` switches in `FContentLoader.cpp` only), or rename the usages `Id→Text`, `IdArray→TextArray`. Not a boundary finding.
- **[High] R19/R22 — `schema_version` wrong type throws an uncaught `nlohmann::json::exception`.** `src/core/data/FContentLoader.cpp:134` `document.value("schema_version", 0)` throws `type_error` when the key exists but is a string/array/object, or when the document is not an object (top-level array). `FContentLoader::load` has no try/catch (unlike `AssetManager.cpp:52-56`), so a malformed asset terminates instead of logging nullopt. **Smallest fix:** guard `if (!document.is_object()) { LOG_ERROR(...); return nullopt; }` and read the version via `find` + `is_number_integer()` check, no `.value()`.
- **[High] R22 — duplicate row `id` is accepted silently.** The row loop `src/core/data/FContentLoader.cpp:137-207` never checks uniqueness; `FContentTable::find` (`src/core/data/FContentTable.h:15-22`) returns the first match, so a duplicated id silently shadows a later row with no log. **Smallest fix:** collect ids in a local `std::unordered_set<std::string>` (only `insert`, order not used) and `LOG_ERROR(...); return std::nullopt;` on a repeat.
- **[Medium] R23 + contract §Boundary — string-key JSON reads are in `core/`, not `gameplay/data/`, and lack `// boundary:`.** `src/core/data/FContentLoader.cpp:141,145,165,181,192` perform the actual string-key reads; the contract says these "happen only inside `src/gameplay/data/*` decoders, each such line carrying `// boundary:`" — but `gameplay/data` decoders (`FUnitContent.cpp`, `FSkillContent.cpp`) read typed `FContentRow` and never touch JSON. **This is a finding about the declared boundary (item 4).** **Smallest fix:** add `// boundary:` to those `FContentLoader.cpp` lines and amend the allowlist/contract to name `src/core/data/FContentLoader.*` as the string-key boundary (see ruling below).
- **[Medium] Design-미결 — provisional balance numbers in assets are indistinguishable from confirmed values.** `assets/data/units.json` rows carry `max_health:120/80` and `speed:4/6`; `game-design.md:136-140` confirms only the *AP provisional* values (move 1 / skill 2) and speed-based initiative, **not** HP/speed magnitudes. G6 declares these prototype rows, but JSON cannot carry `// 미결` (G7), so the provisional status is invisible in the asset. **Smallest fix:** adopt G7 candidate ① — declare a schema `"$comment"`/`"provisional": true` field (add to `kUnitFields`/`kSkillFields`) or move the prototype rows to `tests/` fixtures.
- **[Medium] R19③ — no test seam for the new loader.** No `tests/` fixture or `tests/changeability/fixtures` entry exercises `FContentLoader::load` (missing/unknown/wrong-type/duplicate/schema_version cases). **Smallest fix:** add one good + one bad fixture asset and an expected-failure case.
- **[Medium] Process suppression — `.pi-lens.json` disables `no-bit-fields` globally.** `.pi-lens.json` (diff) adds `"rules": {"no-bit-fields": {"disable": ["no-bit-fields"]}}`, which removes the check for every file, not just the C++ headers misparsed as C; no comment records why. **Smallest fix:** scope the disable to the affected glob/language instead of a repo-wide disable, or document the reason.
- **[Low] R1/R12 — `src/core/AssetManager.h:17,35` defines two types** (`FAssetDigest` + `FAssetManager`). Minor basename/content mismatch; acceptable as a boundary detail. **Fix:** move `FAssetDigest` to its own header if R1 is enforced repo-wide.
- **[Low] `src/core/data/FContentRow.h:36-38` — `integer()` truncates `double→int` silently** (`2.9 → 2`). AP/range fields are ints authored as numbers. **Fix:** reject non-integral values at load, or document the truncation.
