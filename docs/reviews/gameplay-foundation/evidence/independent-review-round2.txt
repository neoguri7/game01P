## 2. New findings introduced by the fixes

- **[Low, R33] `src/core/data/EContentFieldType.h:11` claims a guarantee the code
  does not implement.** The comment says `Id` is *"validated as a cross-table
  reference"*, but `FContentLoader::readValue` (`src/core/data/FContentLoader.cpp:67`)
  treats `Id` byte-for-byte like `Text`; no cross-table check exists in the loader.
  The only cross-table validation in the repo is the hand-written skill loop at
  `src/gameplay/data/FContentRegistry.cpp:49-54`. The enum comment overstates the
  mechanism (R33: comment must not lie).
- **[Low, R20/R1] `Id` is unreachable for the id field and unused elsewhere.**
  The id-field probe requires `schema.fields[i].type == EContentFieldType::Text`
  (`src/core/data/FContentLoader.cpp:161`), so a schema that declares its identity
  field as the newly added `Id` type is rejected with "id field … is not a
  declared text field" (`:166-168`). Also `EContentFieldType::Id` (singular) has
  zero uses; only `IdArray` is used (`FUnitContent.h:35`, `FSkillContent.h:31`).
  A type added for row identity that cannot be used for row identity is a trap.
- **[Low, record honesty] `pass-2.md:101-102` overstates the `FAssetDigest` split.**
  It claims moving `FAssetDigest` to its own header "also removes nlohmann from
  every includer". False: `src/core/AssetManager.h:3` includes
  `src/core/FAssetDigest.h:3` `#include <nlohmann/json.hpp>`, so every includer of
  `AssetManager.h` (e.g. `src/core/data/FContentLoader.h:3`,
  `src/gameplay/data/FContentRegistry.h:3`) still pulls nlohmann. Functionally
  harmless, factually wrong in the record.
- **[Low, evidence quality] `docs/reviews/gameplay-foundation/evidence/compiler-syntax-check.txt`
  is 7 lines of TU filenames only** — no compiler command, no exit code, no
  output. `pass-1.md`/`pass-2.md` cite it as proof the `cl /Zs` check was clean,
  but the file cannot substantiate that. Record needs the actual command + result,
  or the citation weakened.

None of the four is a Blocker/High; all are documentation/record precision, not
runtime correctness.

## 5. pi-lens false-positive claim — VERIFIED

Claim under test: the `no-bit-fields` hits on `src/core/data/FContentValue.h`
(lines 14,15,17) and the `file not found` include chains are pi-lens engine false
positives (`.h` dispatched as C), not real defects.

Evidence:

1. **Mechanism reproduced from the analyzer source**, pi-lens `4.1.6`
   (`C:/Users/marti/.pi/agent/npm/node_modules/pi-lens/dist/index.js:48221-48222`):
   ```text
   c: [".c", ".h"],
   cpp: [".cpp", ".hpp", ".cc", ".hh"],
   ```
   `.h` is mapped to **C**, `no-bit-fields` is a `language: c` rule. Confirmed.
2. **No bit-field syntax exists at the cited lines.** `src/core/data/FContentValue.h:14`
   is `EContentFieldType type = EContentFieldType::Text;`,
   `:15` is `std::variant<...> value{std::string{}};` (brace-init of a member, not
   `name : width`), `:17` is `asText()`. A C parser reading `enum class`/`std::variant`
   brace-init produces exactly this kind of spurious `no-bit-fields` hit. **0 real
   bit-fields** in the file.
3. Same signature explains the `pp_file_not_found` chains: C-dispatching a C++
   header whose includes (`<string>`, `<variant>`, `"core/data/..."`) are not on
   the C include path yields `pp_file_not_found` + `unknown_typename`. The
   guideline now records this at
   `docs/guidelines/game-code-changeability.md:698-706` (engine-limit section,
   explicitly cites `FContentValue.h` 14·15·17 and "실제 비트필드 0건").
4. **Refutation attempt:** the earlier guideline claim that these hits appear
   *only in fixtures* is false; the corrected text (verified at `:703-705`) admits
   they appear on `src/` too. So the "false positive" ruling stands, but the
   earlier "fixtures-only" wording was itself wrong and has been corrected — good.

Claim **VERIFIED**. Caveat: because `.h`→C dispatch masks real C++ type errors
(this is exactly how round-1's Blocker slipped past `ok R20 clean`), pi-lens hit
counts must never be used as a PASS count for `src/`. My item-1 verification was
done by source comparison, not by the analyzer.
