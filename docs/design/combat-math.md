# 전투 수학 (원문 §4–§5 발췌)

> 원본: `git show 98d3bf6^:docs/design/game-design.md` (삭제 직전 DRAFT). 아래 인용은 원문 그대로이며 섹션 번호를 붙였다. 상태 표기(확정/잠정/미결)도 원문 그대로 옮겼다.

## 1. 변환 파이프라인 순서 (§5, **확정**: 순서를 문서·UI에 명시)

원문 식: `베이스 스킬 + 룬(태그·형태·강화·상태) → 런 성장(노드 + 물질 스탯) → 최종 수치`

순서 (원문 §5 순서대로):

1. 베이스 스킬
2. 룬(태그·형태·강화·상태)
3. 런 성장(노드 + 물질 스탯)
4. 최종 수치
5. 적용 시 굴림 (치명타) — 아군 스킬의 직접 피해에만, 대상별 1회. 최종 수치 × crit_multiplier_percent / 100, 보스 피해 상한은 그 뒤에 적용. 적은 굴리지 않는다. (WP-39)

원문 근거: "순서를 숨기면 플레이어가 이중 변환을 시도하며 혼란을 겪는다 (Grim Dawn 트랜스뮤터 사례)." (§5)

주의: 2번 항목의 "형태·강화"는 원문에서 §5 개편 3차로 폐기된 **룬 축(속성/형태/강화)**과 같은 단어다 (§5 "폐기(개편 3차): 룬 축(속성/형태/강화)"). 이 목록은 원문 문구를 그대로 옮긴 것이며, 현재 룬 모델이 어떤 태그를 쓰는지는 원문에서 확정되지 않았다.

Owner per stage: 1–4 TBD (filled by WPs that add modifiers); 5 = ActionResolverSystem (roll), PreviewSkill (numbers).

Enemy sheet (separate from the skill pipeline): base → depth and room scale → cycle scale → elite affix (WP-41). Owner: RefreshCombatSheet block ③.

## 2. 피해 공식 (§5, 잠정)

- `피해 = max(1, offense + power − defense)` (잠정) — 원문 §5, "전투에 영향을 주는 요소" 첫 항목 "캐릭터 스탯" 안.
- 원문 전체 문장: "**캐릭터 스탯** — `hp·공격력·마법공격력·속도·방어력·마법방어력`. 클래스 = **전사·궁수·법사** (정본 §1.1/§1.2). 피해 = `max(1, offense + power − defense)` (잠정)."
- 미정의 사항 (원문에 없음): `offense`, `power`, `defense`가 어떤 스탯(공격력·마법공격력·방어력·마법방어력 등)에 대응하는지, 물리/마법 구분이 공식에 어떻게 들어가는지. §5 "스킬은 공격(물리)/주문(마법) 분류 + 태그"만 있고 이 둘을 공식에 연결하는 문장은 없다.

## 3. 전투 수치 규칙 (§4, 확정 unless noted)

- "턴제, 그리드 전장, 파티 최대 4명 직접 조작." (§4)
- "목표 전투 길이: 룸당 3~6분. 던전 15~30분." (§4)
- "**그리드 = 12x12.** 사거리는 칸 단위." (§4)
- 턴 자원 (§4, **확정**, 사용자 결정 m00750, m00756): "**이동 AP** — 이동 전용. 잠정값 턴당 **1**(이동 1회)." / "**스킬 AP** — 스킬 전용. 잠정값 턴당 **2**." / "두 풀은 **서로 전환되지 않는다**. 이동 AP를 스킬에 쓰거나 그 반대는 불가."
- "수치(잠정값, 고비용 스킬의 비용 상한)는 밸런싱 단계에서 조정한다." (§4)
- 미결 (§4, 원문 "미결 (구현 단계에서 점차 결정 — 사용자 결정 m00756)"): "이동 AP·스킬 AP의 최종 수치, 고비용 스킬의 비용 상한." / "AP 회복·추가 AP 부여 수단 여부." / "이동 거리(칸)와 사거리 수치."

## 4. 턴 순서 규칙 (§4, **확정**)

원문 그대로 (§4 "턴 순서 = 속도 기반 이니셔티브 + 순서 예측 표시"):

- "라운드마다 계속 참여한 유닛은 **턴 1회**를 받는다. 행동 1회 제한이 아니며 이동/스킬 AP와 별개다."
- "라운드 시작에 속도를 스냅샷으로 고정하고 높은 속도부터 진행한다. 0도 정상 참여하며, 속도 변경은 다음 라운드부터 적용한다."
- "같은 속도 그룹 안에서만 매 라운드 균등 셔플한다. 연속 라운드에서 같은 순서가 나와도 정상이다."
- "현재 라운드 순서는 표시하되, 다음 라운드 동률 순서는 추첨 전 확정된 것처럼 표시하지 않는다."
- 참조: "프로토타입 API·데모·검증 방법: [turn-system.md](turn-system.md)." (이 추출에서 해당 문서는 읽지 않음)

## 5. 요소 수치 (§5, 잠정 / 정본 참조)

- 캐릭터 기본 스탯 (§5 개편 3차, §9 확정): `hp·공격력·마법공격력·속도·방어력·마법방어력`.
- 스킬 슬롯: "캐릭터별 스킬 슬롯(잠정 4)에 장착하고 거점/정비에서 자유 교체." (§5)
- 룬 소켓: "스킬의 **룬 소켓**(잠정 3)에 장착." (§5)
- 레벨업 노드 포인트: "레벨업마다 노드 포인트 1." (§5, 런 스코프 캐릭터 EXP 기반)
- 강화 룬 상한: "강화 룬 총 위력 +100% 상한(정본 §3.3)." (§5, 수렴 방지, 정본 참조, 원문 본문에서 수치는 이 한 곳)
- 노드 상한: "노드 총 배수 상한(정본 §6)." (§5, 수렴 방지) — 원문 본문에 수치 없음.
- 룬 제한: "룬은 **소켓 수**로 제한한다." (§9 개편 3차) — 소켓 수 자체는 위의 잠정 3.

## 6. 원문에서 확인된 전투 수치 관련 모순·공백

- §5는 "전투에 영향을 주는 요소는 **4가지**다."라고 쓰지만 뒤따르는 항목은 5개다 (캐릭터 스탯, 베이스 스킬, 룬, 강화 물질, 런 EXP→레벨→노드).
- 피해 공식의 `offense`/`power`/`defense`에 대응하는 스탯 매핑 미정의 (위 2절).
- 피드백 파일(game-design-feedback.md G5)은 "§4 피해 공식 없음"이라 했으나, 현재 원문 §5에는 공식이 있다 (원문이 그 뒤 갱신된 것으로 보임).
- 피드백 파일(Q3)은 그리드를 "8x8 확정"이라 했으나 현재 원문 §4는 "그리드 = 12x12"다.
