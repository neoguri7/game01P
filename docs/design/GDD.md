## 1. 개요 (Overview)

| 항목 | 내용 |
| --- | --- |
| 장르 | 로그라이크 + 턴제 전투 + 카드 스태킹(조합·크래프팅) |
| 플랫폼 | PC (자체 엔진: C++23, SDL3, EnTT) |
| 목표 세션 | 1런 15~20분 |
| 판정 기반 | D&D 최소 룰 (d20 판정 엔진, 접근성 우선 변형 구조) |

**컨셉 한 줄**: 카드를 쌓고 조합해 빌드를 만드는 로그라이크 턴제 전투. 룰은 얇게, 카드는 깊게.

**디자인 필라**

1. **카드가 곧 전략** — 룰 복잡도가 아니라 카드 조합이 깊이를 만든다.
2. **조합의 발견** — 베이스(스킬/장비)+룬 조합(룬워드식 레시피, 요소 변화)을 플레이어가 실험하며 배우게 한다.
3. **작은 룰, 명확한 판정** — d20 최소 룰. 모든 판정은 플레이어가 읽을 수 있어야 한다.

## 2. 코어 루프 ✅

```text
런 시작 (캐릭터 4장 등록 → 1장 시작 캐릭터 선택)
  → 던전 탐험 (그래프 맵, 룸 선택 이동)
  → 룸 진입 직전: 카드 테이블 (조합·장착·정비)
  → 룸 클리어 (전투 = 그리드 맵 / 이벤트 / 영입)
  → 다음 룸 선택 → ... → 보스 → 게임 오버 or 클리어
  → 메타 진행 (해금) → 다음 런
```

- 카드 테이블은 **룸 진입 전(룸 선택 시점)에만** 열림. 전투 중 조합·장착 불가.
- 던전 내 **파티 영입 룸**에서 파티원 추가.

## 3. 전투 시스템 ✅

### 3.1 기본 구조

- 턴제, 라운드 단위 진행. 전투는 **그리드 맵**에서 수행 (6.2 참조).
- 라운드 내 유닛 개별 턴. 순서는 이니셔티브로 결정.

### 3.2 이니셔티브

- 전투 개시 시 **1회 굴림, 전투 중 고정**.
- `이니셔티브 = d20 + 공속 (캐릭터 카드 고유)`
- 매복/기습 상황 룰: 첫 라운드 순서 강제 변경 + 기습당한 쪽 행동 불가.

**이니셔티브 수정 규칙**

- 수정 카드(순서 변경류)는 **다음 라운드부터 반영** (라운드 종료 시 정산).
- 모든 유닛은 **라운드당 정확히 1회 행동**. 수정으로 행동 상실·추가 불가.
- 전투 첫 라운드 순서는 수정 불가 (매복/기습 상황 룰만 예외).

### 3.3 자원: AP ✅

- **단일 자원**. 캐릭터별 개별 보유. 마나 등 제2 자원 없음.
- 초기 수치는 캐릭터 카드마다 다름: **낮은 캐릭터 2 ~ 높은 캐릭터 4** ✅
- 강화로 상승 가능, **절대 상한 존재** ✅ (💡 제안: 초기값 +2, 예) 2→4, 4→6)
- 스킬마다 AP 비용. **턴 개시 시 전액 회복** ✅.
- **AP는 스킬 전용**. 이동은 별도 예산 (6.2 참조) — 분리된 이동량은 사실상 두 번째 턴 예산임을 인지하고 균형 설계할 것.

### 3.4 판정 ✅

핵심 원칙: **d20 스케일(소정수)과 데미지 스케일(두 자리 수)은 분리**.

**판정 3종**

```text
물리 공격:   d20 + 명중 보정     vs  대상 방어력
마법 공격:   d20 + 명중 보정     vs  대상 마법방어력
효과 적용:   d20 + 시전 수정치   vs  대상 저항 (저항 단일 통합)
```

**복합 스킬 판정 순서** (피해 + 상태이상 동시 보유 시)

```text
① 공격(피해) 판정 → 명중 시 피해 적용 → ② 저항(상태이상) 판정 → 성공 시 효과 적용
```

- 공격 판정 실패(미스) 시 효과 판정 미실행.

- **명중은 카드 보정 담당**: `명중 보정 = 스킬 기본 보정 + 장비 보정` (소정수, 절대 상한 +10).
  - D&D 원형의 능력·숙련 명중을 카드 보정으로 통합한 **의도적 변형 구조** (접근성·카드 전략 중심)
  - 명중 성장은 장비 파밍으로 → 루트 파밍 동기 부여 (❓)
- **데미지**: `카드 기본 주사위 + (공격력 × 물리 계수%) + (마력 × 마법 계수%)`
  - 계수는 **스킬 카드 고유 데이터** (예: 물리 계열 스킬 = 공격력 80%, 혼합 계열 = 40/40)
  - 공격력·마력 = 데미지 계수 원천 전용 (두 자리 수)
- **효과 적용**: 디버프·상태이상은 저항 단일 스탯으로 통합 판정 (유발 계열 무관)
  - **시전 수정치 = 스킬 카드 고유값** ✅ (명중 보정과 동일 구조 — 카드가 담당, 소정수)
- 위력·데미지 타입·판정 계열은 스킬 카드 고유 데이터가 결정.

## 4. 카드 시스템

### 4.0 통합 크래프팅 모델 — 베이스 + 룬 소켓 ✅

- **베이스(스킬 카드 / 장비) + 룬 소켓** 구조. 룬워드 = 소켓에 꽂힌 룬 조합의 레시피 일치 결과 (D2 룬워드 직계).
- **소켓 개수**: 베이스당 **최대 5개**, 장비/스킬 동일 ✅ (추후 변경 가능). 개별 베이스의 실제 소켓 수 분포는 미정 (❓).
- **소켓팅 규칙 (C 모델)** ✅: 소켓 수 ≥ 레시피 길이, 남는 소켓 허용 — 비레시피 룬은 stat만 제공.
- **룬 중복 허용** ✅: 같은 종류 룬 복수 삽입 가능. 레시피 = 소켓에 넣는 총 개수 기준 (예: 5룬 레시피 = 총 5개, 중복 포함).
- **레시피 매칭** ✅: **순서 무관 조합식 + 부분집합 매칭** — 레시피 멀티셋이 소켓에 삽입된 룬의 부분집합(⊆)이면 발동 (추가 룬·남는 소켓 허용 — C 모델과 정합, 비레시피 룬은 stat만 제공). 삽입 순서 무관.
  - ❓ 복수 레시피 동시 부분 매칭 시 우선순위·중복 발동 미정 (MVP는 풀별 레시피 1개라 충돌 없음).
- **룬 풀 분리** ✅: 스킬 룬과 장비 룬은 별도 풀 (고유 데이터 상이 — 스킬 요소 vs 장비 스탯/어픽스).
- 레시피 일치 → 고유(특수) 효과 발동. 비레시피 → 룬별 stat 상승 / **요소 변화**.
- 기존 "장비 카드끼리 조합", "스킬 카드끼리 조합"은 본 모델로 **대체**.
- 조합은 카드 테이블에서만 가능.
- **표현 계층 원칙**: 시스템 코어 = 형식 중립 데이터 + 레시피 엔진. UI 표현은 타입별 독립 설계 결정(프로토타입 검증 대상, 단순 스킨 아님):
  - 스킬 = **카드 face** ✅ (정보 밀도 우선)
  - 장비 = **아이콘 + 페이퍼돌/소켓 드래그** ✅ (Diablo식 — 줍고 끼우는 상호작용)
  - 룬 = 소켓 드래그 삽입 재료 — **형식 중립**, 표현 방식(작은 아이콘 vs 카드) 미정 (❓)

### 4.1 스킬 카드 ✅

- **고유 효과 + 능력치를 가진 완성 카드** + 룬 소켓 보유.
- 부품 조립 문법(형태+원소+변조) 폐기.
- **고유 데이터(="요소")**: 효과, 판정 계열(물리/마법/효과), 데미지 계수%, 명중·시전 수정치, AP 비용, 고유 사거리, 범위 모양.
- 룬 소켓팅: 레시피 일치 → 특수 스킬(룬워드), 비레시피 → stat 상승 / 요소 변화 (❓ 가변 필드·방식 미정)
- 보관 구분: **카드 보관함**(런 중 인벤토리) / **장착 슬롯**(캐릭터당 개수 제한 ✅).

### 4.2 장비 ✅

- **베이스 아이템 + 룬 소켓** (D2식).
- 착용 = 부위 슬롯(페이퍼돌) 드래그.
- 룬 조합 레시피 일치 → 룬워드 고유 효과. 비레시피 → 룬별 단순 stat 상승.
- 기본 공격 사거리 = 무기 고유값 (6.2 참조).

### 4.3 룬 ✅ (소켓 재료)

- 소켓 삽입 재료. 고유 스탯·속성 보유. 표현 형식 미정 (4.0 참조).
- 풀 규모·획득 경로 미정 (❓).

### 4.4 캐릭터 카드 ✅

- 파티 멤버도 카드. 메타 컬렉션(해금 풀)에 축적.

## 5. 파티 시스템 ✅

```text
메타 컬렉션 (해금된 캐릭터 카드 풀)
  ↓ 런 시작 시 4장 선택 등록
등록 풀 (4장)
  ↓ 그중 1장을 시작 캐릭터로 즉시 선택
시작 캐릭터 1 + 미영입 풀 3장
  ↓ 던전 내 영입 룸에서 플레이어가 직접 선택 (1명씩 합류)
파티 (최대 4인)
```

- 고정 주인공 없음. 시작 캐릭터도 등록된 4장 중 선택.
- 영입 룸 = 미영입 풀에서 1장 선택 합류.
- 전투 파티 상한: **4인**.

## 6. 맵 구조 ✅

### 6.1 던전 맵 — 그래프

- 룸(노드)을 간선으로 연결한 그래프. 룸 선택 이동.
- 룸 유형: 전투 / 영입 / 이벤트 (비율 미정 ❓)
- 카드 테이블은 룸 진입 직전 개방 (독립 룸 아님).
- 그래프 형태(분기 노드맵 등) 세부 미정 (❓).

### 6.2 전투 맵 — 그리드 ✅

- 그리드 규격: **9 × 9** (사각 그리드). 전투는 룸 진입 시 이 전장에서 수행.
- 배치 구역: 아군 측 **하단 3행 × 9열**.
- **이동 = AP와 분리된 별도 턴 예산** ✅ (XCOM/Into the Breach식)
  - 이동량 ✅: **첫 라운드(몬스터 룸 입장 조우 시) 최대 2칸, 2라운드 이후 1칸/턴**. 미사용 이동량 이월 없음
  - 분리된 이동량은 사실상 두 번째 턴 예산임을 인지하고 균형 설계할 것 (3.3 참조)
  - 이동 칸수는 장비/스킬 카드로 수정 가능 (예: 신발 룬워드 "이동+1", 스킬 고유 효과 "시전 후 1칸 이동") → 카드가 기동성 담당, 스탯 추가 없음
- **시야/장애물**: 없음 ✅ (MVP 기준 — 전장 전체 시야 내). 확장으로 추가 의향 있음.
- **적 배치** ✅: 아군 배치 구역(하단 3×9) 외 **상단 6행 × 9열 영역에 랜덤 배치**.
- AP는 스킬 전용 (3.3 참조).
- **사거리** ✅:
  - **기본 공격**: 장착 무기 카드의 사거리 적용 — 근접 무기 1칸, 활 3칸, 스태프 2칸, 석궁 2칸 등 (무기마다 상이)
  - **스킬**: 고유 사거리 — 스킬 카드마다 개별 (고유 데이터), 카드에 표시
- **범위(광역)**: 스킬마다 개별 정의 ✅ (고정 도형 없음 — 각 스킬이 자기 영향 구역 모양을 가짐)
  - 범위 모양 = 스킬 카드 고유 데이터 (카드 풀 설계 시 정의)
- **재배치 시점 3종**:
  1. 런 시작: 3×9 구역에 초기 배치 확정
  2. 영입 직후: 새 캐릭터를 빈 타일에 배치
  3. 전투 종료 시: 전체 재배치 가능 (TFT식).
- 유닛 위치·사거리·범위 판정에 사용.
- **거리·점유 규칙** ✅:
  - 대각선 1칸 = 1칸 (체비셰프 거리). 사거리·이동 모두 이 기준
  - **1칸 = 1유닛**. 점유 불가, 통과 불가 — 아군도 통과 안 됨 (겹침 문제 방지)

## 7. 캐릭터 스탯 ✅

8종 고정. 스케일 2원칙: 명중·목표값 = 소정수(d20 스케일), 공격력·마력 = 두 자리 수(데미지 스케일).

- **명중은 스탯에 없음**: 카드 보정(스킬 기본 보정 + 장비 보정)만 사용 — 접근성 위한 변형 구조 (3.4 참조).
- 캐릭터 카드가 스탯 초기값 + 고유 특성 보유.
- 성장 체감: 공격력/마력↑ = 데미지, 명중 성장은 장비로 분리.

| 스탯 | 역할 | 스케일 |
| --- | --- | --- |
| HP | 생명력, 0 이하 = 전투 불능 | 두 자리 수+ |
| AP | 턴 자원, 초기 2~4, 상한 존재 | 소정수 |
| 공격력 | 물리 데미지 계수 원천 (롤 판정 미사용) | 두 자리 수 |
| 마력 | 마법 데미지 계수 원천 (롤 판정 미사용) | 두 자리 수 |
| 공속 | 이니셔티브 수정치 (`d20 + 공속`) | 소정수 |
| 방어력 | 물리 공격 목표값 | 소정수 |
| 마법방어력 | 마법 공격 목표값 | 소정수 |
| 저항 | 디버프·상태이상 적용 목표값 (단일 통합) | 소정수 |

## 9. MVP 수직 슬라이스 ✅ (범위)

목표: **룬워드 1개를 끝까지** — 획득 → 소켓팅 → 레시피 발동 → 전투 검증.

포함:

- 룬워드 레시피: **풀별 1개씩** ✅ (스킬 룬워드 1 + 장비 룬워드 1, 각 총 5룬, 중복 허용)
- 룬 종류: **풀별 3종** ✅ (중복 허용이므로 5칸 구성 가능, 예: A×3 + B×2)
- 베이스 **2종**: 스킬 카드 1(5소켓) + 장비 1(5소켓) — 양쪽 소켓팅 검증
- 룬 획득 경로 최소 1종 (전투 드랍)
- 최소 전투: 캐릭터 1 + 적 1, 기본 공격 + 룬워드 발동 효과 확인
- 카드 테이블: 소켓팅 UI만 (드래그 삽입)

불포함 (후속):

- 파티/영입, 그래프 맵(단일 룸 대체), 메타 진행, 추가 레시피/카드 풀
