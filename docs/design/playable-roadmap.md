# Playable Roadmap — 플레이 가능 수준까지의 구현 계획

Status: **DRAFT**

이 문서는 [game-design.md](game-design.md)가 요구하는 게임을 **"플레이 가능한 수준"**까지
끌어올리기 위한 구현 계획이다. 장르·런 구조·누적 규칙의 원천은 game-design.md이며,
이 문서는 그 계약을 **현재 코드와의 격차**로 번역한다. 충돌 시 game-design.md가 우선한다.

관련 문서:

- [game-design.md](game-design.md) — 게임플레이 계약 (장르/런/전투/빌드/메타)
- [turn-system.md](turn-system.md) — 턴 스케줄링 프로토타입 (구현 완료)
- `PROJECT_VISION.md`, `docs/guidelines/game-code-changeability.md` (R1~R33) — 변경 용이성 규칙

표기:

- **있음** — 이미 구현됨.
- **없음** — 미구현.
- **게이트** — 미결 결정/선행 작업이 없으면 착수 불가.

## 1. "플레이 가능한 수준"의 정의

= **vertical slice 1개**. 거점에서 런을 시작해 8x8 그리드 턴제 전투(파티 4명, AP 2종)를
수행하고, 몬스터 룸 3 + 이벤트 룸 1을 지나 던전 클리어 또는 전멸로 런이 끝나는
**한 사이클 전체**가 사람 손으로 돌아가는 상태. 빌드 3층·메타는 최소 골격만.

최소선 = **0 → 1 → 2단계 완료**. 이 시점에 앉아서 전투 1판을 직접 칠 수 있다.

---

## 2. 설계가 요구하는 하드 제약 (순서에 반영)

game-design.md에서 **확정**된 항목으로, 구현 편의를 위해 바꿀 수 없다.

- 턴제, **8x8 그리드**, 파티 최대 **4명**, 전원 직접 조작 (§1, §4)
- **AP 2종 분리**: 이동 AP 1(이동 전용) / 스킬 AP 2(스킬 전용), 상호 전환 불가 (§4)
- **턴 순서 = 속도 기반 이니셔티브 + 순서 예측 표시** (§4) — 스케줄러는 구현됨
- **캐릭터 부상·사망 없음**, 전투 KO는 페널티 누적 없음 (§4, §6.1)
- **파티 전멸 = 런 종료 + 런 스코프 초기화** (§2)
- 진행 체크포인트 = **클리어한 던전 개수** (테마 아님) (§2)
- **장비 영속**(창고 누적), 수치노드·룬·파편은 런 스코프 (§2, §5)
- 수치·아이템·스킬·룸 정의는 `assets/data/*.json` (+ `schema_version`), 하드코딩 금지 (§8)
- 시스템 간 통신은 **typed event**, 문자열 디스패치 금지 (§8)
- 변환 파이프라인 순서 고정: `로컬 스킬 변형 → 장비 전역 변환 → 오라/패시브 배수` (§5)

- 존재하나 **`Engine`에 연결되지 않음** (`Engine::update`에
  `// TODO: optional state machine update`). `Update()`는 전부 `return None`.

`assets/data/` 디렉터리, 게임플레이 테스트 타깃.

## 4. 큰 틀 (의존 순서)

```text
0. 토대 정리      상태머신 연결 + 데이터 레이어 + factory/씬 규약
1. 전장 그리드    타일/점유/배치/그리드 렌더/카메라/선택
2. 전투 코어      HP·스탯·AP·행동 해석(이동+스킬)·데미지·KO·승패
3. 스킬/타게팅    스킬 데이터·사거리·대상 선택 + 기본 AI
4. 런/던전 루프   룸 시퀀스·정비·체크포인트·전멸 리셋
5. 거점           편성/로드아웃/창고/런 시작
6. 빌드·파밍      장비·룬(변형)·수치노드·드롭·분해
7. 메타·영속      명단·레벨·해금(L2/L3)·세이브
8. UI/콘텐츠      연출·콘텐츠·밸런스
```

각 단계는 **아래 단계의 완료 기준(DoD)을 통과해야** 다음으로 넘어간다.

## 5. 단계별 구현 계획

### 0단계 — 토대 정리 (선행 필수)

목표: 이후 모든 내용물이 하드코딩 없이 얹힐 수 있는 바닥.

작업:

- `GameStateMachine`을 `Engine::update`/`render` 경로에 연결. `Boot → Title → Hub → Battle`
  전이 배선. 상태별로 필요한 시스템만 실행하는 구조 도입(현재는 `updateAll` 일괄).
- 데이터 레이어: `assets/data/` 디렉터리 + `schema_version` 규약. JSON 로더 유틸
  (시스템 아님). 로딩 실패는 진단 메시지로 표면화.
- 엔티티 factory(유닛/스킬/룸/장비 생성)와 씬 로드/언로드 규약.
- 이유: 이후 전부 JSON + factory 전제. 없으면 하드코딩 → R17/R22 위반.

DoD:

- Title에서 Hub로, Hub에서 더미 Battle 씬으로 전이된다.
- `assets/data/*.json` 하나를 로드해 엔티티를 factory로 생성하는 경로가 있다.

의존: 없음.

### 1단계 — 그리드 전장

목표: 전장이 보이고 유닛이 칸 단위로 놓인다.

작업:

- 정수 격자 컴포넌트(`FGridPosition` 등), 타일 점유 조회(`FGridOccupant` 또는 그리드 ctx).
- 진영 태그(`FPartyMember` / `FEnemy`).
- 그리드 렌더 시스템(8x8, 칸↔월드 변환). `FCamera` 이동/줌 실사용.
- 마우스/키보드 유닛 선택, 이동 가능 칸 하이라이트.

DoD:

- 8x8 격자가 렌더되고, 유닛이 정수 칸에 배치된다.
- 유닛을 선택해 이동 가능 칸이 표시된다.

의존: 0단계.

게이트: `FPosition`(float) ↔ 그리드(정수) 변환 경계를 정해 문서화. 전투에서는 cute_c2
물리를 쓰지 않는다.

### 2단계 — 전투 코어 (첫 "플레이 가능")

목표: 아군 4 vs 적 N, 턴제로 실제 승패가 나는 전투 1판.

작업:

- `FHealth`, `FStats`(장비 + 수치노드 합산), `FMoveAp` / `FSkillAp`(턴 시작 시 리셋).
- 액션 요청 큐 → 액션 해석 시스템(이동/스킬). 이동은 정수 칸 단위.
- 데미지·KO·승패 판정. 턴 종료 시 기존 `TurnController`(`FTurnToken` 흐름)와 연동.
- HUD 최소: 현재 턴 액터, AP, 이동/스킬 버튼, 턴 종료.
- 게임플레이 로직을 테스트 가능한 라이브러리로 분리 검토(순수 로직 = 테스트 가치 큼).

DoD:

- 턴 순서대로 아군/적이 행동하고, 데미지로 KO가 발생하며, 승패로 전투가 끝난다.
- 이동 AP 1 / 스킬 AP 2가 각각 강제된다.

의존: 1단계 + 턴 스케줄러(있음).

### 3단계 — 스킬·타게팅·AI

목표: 스킬로 싸우고 적이 반응한다.

작업:

- 스킬 데이터(비용, 사거리, 형태, 태그). 사거리/영향범위 표시, 대상 선택.
- 적 기본 AI(접근 → 공격). 적 행동도 같은 액션 해석 파이프라인을 통과시킨다.
- 스킬 태그 부여 골격(§5 "2층 — 태그 상호작용"의 토대).

DoD:

- 여러 스킬을 사용하고, 적 AI가 접근·공격한다.
- 스킬이 태그를 부여하고 그 태그가 UI에 보인다.

의존: 2단계.

### 4단계 — 런/던전 루프

목표: 거점 → 전투 → 정비 → 다음 던전이 실제로 이어진다.

작업:

- 런 상태(ctx): 런 스코프 캐릭터 EXP, 파편, 룬, 현재 던전 인덱스.
- 룸 템플릿 JSON + 시드 생성기(몬스터 3 + 이벤트 1~2).
- 룸 전환. 정비(캠프) 지점: 저장(이어하기) + 강화/교체 1회.
- 던전 클리어 → 체크포인트 전진(클리어한 던전 개수).
  전멸 → 런 종료 + 런 스코프 리셋(장비·진행도는 유지).

DoD:

- 거점에서 런을 시작해 룸 3개를 통과하고, 클리어 또는 전멸로 런이 끝난다.
- 전멸 시 런 스코프 요소만 소실되고 진행도·장비는 남는다.

의존: 2·3단계.

게이트: 이벤트 룸 종류 목록, 드롭 기대값 등 §7의 미결 항목. 잠정값으로 시작하고
문서에 확정 필요.

### 5단계 — 거점

목표: 재시작 마찰 목표(전멸 → 다음 첫 전투 2분 이내)를 만족하는 준비 화면.

작업:

- 편성(파티 4명), 로드아웃(스킬 선택), 장비 창고, 런 시작.
- 정비와 거점이 공유하는 준비 UI 정리.

DoD:

- 거점에서 파티·스킬·장비를 정하고 런을 시작할 수 있다.

의존: 4단계.

### 6단계 — 빌드·파밍

목표: 파밍이 빌드 선택지를 열고, 빌드가 드롭 가치를 바꾼다 (§1).

작업:

- 장비 획득/장착/분해(→파편), 드롭 3계층(trash / 어픽스 롤 / 유니크).
- 룬(변형 슬롯, 무료 교체), 수치노드(캐릭터별 트리, 런 스코프 EXP가 포인트 공급).
- 변환 파이프라인 순서 고정: `로컬 변형 → 장비 전역 변환 → 오라/패시브 배수`.

DoD:

- 한 런 안에서 정비 지점마다 빌드가 1회 이상 바뀐다.
- 룬이 스킬의 **동작**을 바꾸고, 수치노드가 수치를 바꾼다(경계 준수).

의존: 4단계.

게이트: 어픽스 풀·티어·리롤 비용, 드롭 기대값(§7 미결).

### 7단계 — 메타·영속

목표: 런 사이에 남는 층을 확정한다 (§6).

작업:

- 2종 EXP: 누적 캐릭터 EXP(영속 → 캐릭터 레벨 → 스킬 해금),
  런 스코프 EXP(런 스코프 → 수치노드 포인트).
- 거점 레벨 → 장비 해금.
- L1 명단, L2 승격(스킬 슬롯 +1, 변형 +1, 상한 고정), L3 풀 해금.
- 세이브/로드(정비 지점 저장).

DoD:

- 런 실패 후에도 명단·레벨·해금·장비 창고가 유지된다.
- 누적은 "정체성/옵션"을 미리 지불하고 "파워"를 미리 지불하지 않는다(§6).

의존: 5·6단계.

게이트: 명단 상한(제안 12), 새 캐릭터 획득 경로, 인장 수치(§6 미결).

### 8단계 — UI·연출·콘텐츠·밸런스

- 턴 순서 예측 표시, 스킬 아이콘/태그 배지, 슬롯 장착 결과 미리보기.
- 승격 조합 최초 발견 연출 + 도감 해금.
- 몬스터/스킬/룸/장비 콘텐츠 채우기.
- 수직 누적 안전 기준 측정: 1번째 런 vs 20번째 런 승률 차 10~20%p 이내.
  승률만 보지 말고 "같은 실력 구간의 시작 파워"를 별도 측정 (§6).
