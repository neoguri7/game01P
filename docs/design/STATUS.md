# 현재 상태 (2026-11-11)

새 세션이 이 파일 하나로 이어갈 수 있게 쓴 요약이다. 자세한 내용은 가리키는 문서에 있다.

## 1. 구현 — 어디까지 되어 있나

main에 병합되어 있고 빌드와 테스트가 통과한다. origin보다 앞서 있으며 푸시하지 않았다.

| WP | 내용 | 상태 |
|---|---|---|
| WP-39 | 치명타, 전투 목표(보너스 목표) | 병합 |
| WP-40 | 룬 희귀도: 등급 3개, 확률표 3종(일반·상향·보스), 보상 카드에 적용 대상 미리보기 | 병합 |
| WP-41 | 던전 갈림길: 방 사이의 선택(표준 / 변형), 엘리트 전투, 이벤트 6종, "?" 방 | 병합 |

이 셋은 **아직 한 번도 사람이 플레이해 보지 않았다.** 규칙상 다음 플레이테스트 전에는 플레이어에게 보이는 변경을 더 내보내지 않는다.

지금 게임에 있는 것:
- 12x12 격자, 아군 4(전사·궁수·법사·치유 역할) 대 적 3~4. 이동 2칸, 이동과 스킬은 따로.
- 벽이 이동과 사선을 막는다. 적 의도가 표시되고, 대상이 벗어나면 빗나간다.
- 런: 준비 화면(스킬 4개씩 선택) → 던전(전투 방, 보상, 이벤트, 갈림길) → 캠프(회복, 강화, 룬 구매) → 다음 던전.
- 보스는 Stone Guardian 하나만 작성되어 있다. 나머지 보스 자리는 범용 유닛이다.
- 런 로그: 세이브 폴더의 `run_logs/run-<n>-<n>.jsonl`에 방마다 한 줄씩 남는다(피해, 적 의도 빗나감, 보상 선택, 갈림길 등).

없는 것: 런의 승리 화면, 두 번째 적 AI, 유물, 런 로그 집계 도구, `docs/playtest/` 폴더.

이번 세션 끝에 고친 것: 오토파일럿이 준비 화면에서 Start를 누르지 않아 자동 실행이 멈추던 문제(`src/dev/FRunAutopilot.cpp`).

## 2. 설계 — 어디까지 되어 있나

| 문서 | 내용 | 상태 |
|---|---|---|
| `decisions.md` | 사용자의 결정(확정·가정·미결) | 기준 문서. 확정은 사용자만 바꾼다 |
| `expansion-plan.md` | WP-39~41의 게임 설계 | 구현 끝 |
| `foundation.md` | 뼈대 10개 층(L0~L9)마다 명작의 근거, 지금 상태, 판정 | 7라운드 반영. 더 다듬어도 얻을 것이 적다 |
| `proposals.md` | 미결 항목 P0~P10의 선택지·비용·권고·약점 | 3차 초안. **전부 승인받지 않았다** |
| `../wp/FOLLOW-UPS.md` | 리뷰와 조사에서 나온 후속 항목 | 계속 추가 |

`proposals.md`의 항목과 권고(권고일 뿐 결정이 아니다):
- P10 플레이테스트 절차 — 질문·관찰·지표·문턱 표. 문턱은 제안값이다.
- P0 인장 예산(벌 수 있는 양 16, 목록의 값 35) — 수량을 데이터로 옮기고 다시 맞춘다.
- P1 런의 끝 — 먼저 기존 "대단원"을 승리로 보여주고 런은 계속한다.
- P2 런 로그 추가 항목과 집계 도구 — 만들지 물었고 답을 받지 못했다.
- P3 재료와 회복 — 지금대로 두고 측정한다.
- P4 파티 유물 — 스스로 세운 규칙을 통과하는 후보가 없다. 보류.
- P5 경험치 — 확정 문구를 구현(방 클리어 시 전원 동일)에 맞춘다.
- P6 위치의 깊이 — 측정 → AI 확인 → 엘리트를 무거운 방에서.
- P7 최종 보스 작성, P8 거점은 지금대로, P9 온보딩은 플레이테스트 뒤.

구현이 확정과 다른 곳 다섯 군데는 `foundation.md` §2의 표에 있다.

사용자의 답을 기다리는 가정 둘(`decisions.md`): 룬 등급표 8/8/8, 보상 카드의 미리보기 3줄.

## 3. 다음: 창을 띄운 플레이테스트

실행(사용자의 실제 세이브는 `%APPDATA%\Game01P`에 있다. 건드리지 않으려면 `GAME01P_SAVE_DIR`을 준다):

```powershell
node .claude/scripts/build.mjs --preset windows-msvc-agent
$env:GAME01P_SAVE_DIR = "D:\repos\game01P\out\playtest"
.\out\build\windows-msvc-agent\Debug\game01P.exe
```

같은 런을 다시 보려면 `GAME01P_SEED=<숫자>`. 자동으로 돌리려면 `GAME01P_AUTOPLAY=1`(전투)과 `GAME01P_AUTOPILOT=default`(보상·이벤트·캠프)를 함께 준다.

볼 것:
- `proposals.md` P10의 표.
- `FOLLOW-UPS.md`의 플레이테스트 확인 항목: 엘리트 선택지 옆의 예측 줄, 룬 카드와 갈림길 패널이 함께 뜰 때 이벤트 창의 높이.
- 1280x800에서 보상 창이 스크롤 없이 들어가는지(WP-40).

메모는 `docs/playtest/YYYY-MM-DD.md`에 사용자의 말 그대로 적는다. 에이전트는 고쳐 쓰지 않고 WP 가설이나 `decisions.md` 항목으로 분류한다.

## 4. 창 없는 자동 실행에 대해 알려진 것

- 동작한다: 시드 1로 방 3개를 끝냈고, 같은 시드의 런 로그가 두 번 같았다.
- 느리다: Debug 빌드가 SDL dummy 드라이버에서 초당 13프레임쯤 나와 전투 하나에 35초쯤 걸린다.
- 빠르게 하는 방법(그리기 건너뛰기, Release 빌드)은 시도하다 중단했고 코드에 남기지 않았다.
